# InfraPolus - Filosofia

InfraPolus no se define por lo que hace, sino por el orden en que decide. Ante cualquier disyuntiva de diseno, estas prioridades resuelven el empate. Son los "porque" detras de cada "como".

**InfraPolus prioriza:**

- **Comprension antes que automatizacion.** Primero entender el problema y el dominio; automatizar despues. Un sistema que automatiza lo que no comprende amplifica errores.
- **Arquitectura antes que features.** Una feature mal ubicada es deuda; una frontera bien puesta es capacidad futura gratis.
- **Observabilidad antes que complejidad.** No se agrega complejidad que no se pueda observar. Lo que no se ve, no se puede razonar ni corregir.
- **Extensibilidad antes que optimizacion.** Optimizar temprano congela decisiones; extensibilidad las mantiene abiertas. Se optimiza cuando la frontera ya es estable.
- **Correctitud antes que velocidad.** Una respuesta rapida y errada es peor que una lenta y correcta. La velocidad es una optimizacion, no un requisito fundacional.
- **Conocimiento antes que generacion.** El valor del sistema esta en lo que sabe y como lo estructura, no en lo bien que redacta. La generacion es la superficie; el conocimiento es la sustancia.

**Corolario rector:** cuando dos principios choquen, gana el que aparece primero en esta lista. Esta jerarquia es la constitucion de InfraPolus; el resto de los documentos la implementan.
